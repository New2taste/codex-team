# 常驻路由器选型研究设计

## 目标

在不改变确定性有效路由的前提下，实测 Luna、Sol、Terra 三个模型家族中，
谁更适合作为低成本的常驻入口路由器。研究同时允许得出“三者都不值得常驻”
的结论。在实测完成前，项目说明建议优先考虑 Luna max 作为常驻入口分类候选；
这不是实验结果，也不改变生产生效路由，实际选择仍由使用者决定。

## 关键定义

“常驻”固定为：

> 固定模型 + 冻结提示词前缀 + 每次调用新会话 + 同一实验臂在缓存时间窗内聚簇运行。

不把同一个长线程跨任务复用作为生产候选。长线程会造成跨任务污染、上下文
膨胀和截断后前缀突变；它与服务端前缀缓存不是同一个概念。

模型切换、会话切换、推理档位变化是否造成缓存失效都属于待实测假设。直接
证据只有每次调用的 `input_tokens`、`cached_input_tokens`、固定前缀哈希和
调用间隔。

## 安全边界

- 全程 shadow-only；模型输出不能改变 `effective_route`。
- 当前确定性路由器是零成本基线和最终兜底。
- 探针只读、每次新会话，不复用任务上下文。
- live 探针需要配置 `enabled=true` 与 CLI `--allow-live-model` 双钥匙，配置模型矩阵必须与代码闭集一致。
- 离线研究不 import `WorkflowStore`，不写 task store 或事件账本。
- 实验产物只写独立实验根目录。
- R4 生产集成不在本轮范围；它必须等 S3/S4 联合 live exit 0 后另行批准。

## 实验 0：缓存失效因子探针

用同一微型入口分类任务，每次只改变一个因素并重复测量：

1. 同模型、同前缀、新会话；
2. 换模型、前缀不变；
3. 同模型、改变前缀；
4. 同模型、同前缀、改变 reasoning effort；
5. 同模型、同前缀、改变调用间隔。

结果记录为观测，不预设“换模型必然清空缓存”。研究结束时重跑一次，检查
服务商缓存行为是否漂移。

## 主实验

采用离线、只读、配对重放：

- 四个任务层：类 L0、类 L1、需规划、对抗/歧义；
- 每层至少 8 个案例，共至少 32 个；
- 每个案例运行 Luna/Sol/Terra 的热前缀臂和对应冷前缀对照；
- “不常驻”控制组是三个冷对照的汇总，避免把模型差异和常驻差异混在一起；
- 当前确定性路由不调用模型，作为绝对零成本基线；
- 同一真实写任务不得重复执行，历史案例只重放入口分类；
- 固定随机种子决定实验臂顺序；每个热臂内部聚簇执行，首调冷、后续热分别报告。

## 指标与判定

成本轴：

- cache hit ratio；
- uncached input tokens；
- 总 input/output tokens；
- 路由器额外时延；
- 路由器开销与历史任务成本的比例。

质量轴：

- 与确定性路由的一致率；
- 首交通过率；
- P0/P1 miss；
- 对抗样本的越权或误放行。

两条轴分开设门，不合成单一分数。任何 P0 误分流直接淘汰该实验臂。未达到
最小样本数时只能输出 `OBSERVATION_ONLY`。通过质量门的候选中，只能先按稳态
uncached input 标记 `CACHE_MECHANISM_CANDIDATE_*`；没有带日期/来源的费率快照
和下游反事实成本时不得声称真实成本赢家。若没有候选产生足够缓存收益，则保持现状。
“足够缓存收益”固定为同模型 warm-tail 相对 cold control 的平均 uncached input
至少下降 30%；该阈值只签发机制候选，不构成 R4 或 enforced 授权。

## 最小数据模型

复用 `cost-evidence-1` 的 token、时延、质量和 paired-case 字段。新增：

- 闭集成本角色 `router_probe`，只用于实验账本，不能参与生产路由；
- `router-probe-manifest-1`，记录 batch、arm、模型、推理档、冷热条件、
  固定前缀哈希、模板版本、随机种子、案例、attempt、时间和 surface。

manifest 与 cost evidence 通过 `attempt_id` / `paired_case_id` 连接。

## 施工分卡

### R1：契约与配置

增加 `router_probe` 成本角色、三模型闭集探针配置和 manifest schema。所有
探针配置只读；未知模型、arm、cache condition、额外字段必须拒绝。

### R2：离线探针运行器

新增独立标准库脚本，支持 `dry-run`、fake executor 和受显式
`--allow-live-model` 保护的 live executor。它只接受冻结案例清单，生成
manifest 和 cost evidence，不接触 task store。

### R3：聚合与报告

读取 R2 产物，按模型和冷热条件计算缓存曲线、成本差、样本数和质量门。数据
不足、合成数据或缺失 token 时不得给出支持常驻的结论。

## 停止线与回滚

遇到只读权限漂移、P0 误分流、预算上限、缓存行为不可重复或服务商语义漂移
立即停止。研究是独立 shadow 产物；回滚只需删除实验目录并撤回 R1–R3，
生产路由从未改变。
